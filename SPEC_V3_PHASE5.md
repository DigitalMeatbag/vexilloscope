# vexilloscope v3 Phase 5 Specification: Historical Import, Bot Migration, and Batch JSON

> **Purpose:** Implementation specification for vexilloscope v3 Phase 5. Derived from `FOUNDATION_V3.md` and building on `SPEC_V3_PHASE4_MODEL_OUTPUT.md` and its predecessors. This document covers three threads: historical flag import infrastructure, Discord bot migration to `--identify-json`, and `--identify-json-batch` mode in the C binary. Do not implement anything in a later phase from this document.

---

## 1. Purpose and Scope

Phase 5 builds on the Phase 4 infrastructure (`--identify-json`, `class_meta.tsv`, `confusable_pairs.tsv`) to deliver the first historical flag expansion and complete the bot migration that Phase 4 deferred.

**Thread A — Historical Flag Import:**
- `scripts/historical_seed.csv` — human-curated seed list of historical flags (checked into repo)
- `scripts/import_historical.py` — Wikimedia-based import script following the Phase 2 pattern
- New manifest records in `data/manifest/flags.jsonl` and `data/manifest/assets.jsonl`
- Source SVG assets under `data/sources/wikimedia/historical/`
- Import reports under `reports/import/wikimedia/<timestamp>.json`

**Thread B — Bot Migration to `--identify-json`:**
- Updated `bot/bot.py`: subprocess call changed to `--identify-json`, RESULT_RE removed, JSON-based response formatting with `short_description`, confidence, and ambiguity notes

**Thread C — `--identify-json-batch`:**
- Updated `src/main.c`: `--identify-json-batch <file>` flag; newline-delimited JSON output, one object per image

**Phase 5 does not touch:**
- Flags of defunct states (USSR, Ottoman Empire, Czechoslovakia, Yugoslavia, etc.) — deferred to Phase 6
- No-flag class, flagness head, hard-negative mining — separate spec
- `exp-balanced-sampling` — deferred; low expected value until Phase 6+ multi-source expansion creates meaningful per-class asset imbalance
- `--identify` text output format (unchanged)
- `--identify-batch` TSV output (unchanged)
- Expansion beyond historical national flags (fictional, pride, cultural, maritime, military)
- `data/manifest/results.jsonl` — existing result records are not modified; no new result records are created (Phase 5 historical flags share existing national result entries)
- `scripts/validate_manifest.py` unless it rejects `era_start`/`era_end` on flag records (check and fix only if needed)
- `reports/eval/v3-baseline/` and `reports/eval/exp-256-p16/` (immutable)

## 2. Foundation Decisions Summary

All decisions below are closed in `FOUNDATION_V3.md` and are not re-opened in this spec.

| Decision | Value |
|---|---|
| Historical flag `status` | `historical` on flag records |
| `era_start` / `era_end` | Optional string fields on flag records; four-digit year string (e.g. `"1933"`) or omitted |
| `result_id` for historical flags | Reuse existing national `result_id` (e.g. `"de"` for all German historical flags) |
| Defunct states | Deferred to Phase 6; Phase 5 only imports historical flags of currently existing countries |
| Import mechanism | Curated seed CSV → Wikimedia Commons API fetch → manifest records with `review_status=imported` |
| `trainable` default | `false`; promoted to `true` only after manual human review |
| Bot output contract | `--identify-json` replaces `--identify`; RESULT_RE removed; JSON parsed directly |
| Batch JSON output format | Newline-delimited JSON; one complete JSON object per image |
| `class_meta.tsv` / `confusable_pairs.tsv` | Generated by `export_training.py` (Phase 4 deliverable); no changes to generation logic in Phase 5 |
| Phase 5 complete definition | All three threads implemented AND `--identify-json` bot path verified end-to-end |

## 4. Thread A: Historical Flag Import

### 4.1 Seed File — `scripts/historical_seed.csv`

Human-authored CSV, checked into the repo. This is the human curation layer for Phase 5 — the importer is a mechanism; the actual flags to import are determined by what rows appear here.

**Columns:**

```
result_id,era_descriptor,era_start,era_end,display_name,wikimedia_filename,short_description
```

| Column | Required | Description |
|---|---|---|
| `result_id` | yes | Existing national `result_id` (e.g. `de`, `fr`, `gb`) |
| `era_descriptor` | yes | Short slug appended to `result_id` to form `flag_id` (e.g. `1933`, `weimar`, `first-republic`). Lowercase, hyphen-separated. |
| `era_start` | no | Four-digit year string (e.g. `1933`); empty if not applicable |
| `era_end` | no | Four-digit year string (e.g. `1945`); empty if ongoing or not applicable |
| `display_name` | yes | Human-facing display name (e.g. `Germany 1933–1935`) |
| `wikimedia_filename` | yes | Exact Wikimedia Commons file name including extension (e.g. `Flag_of_Germany_(1933-1935).svg`) |
| `short_description` | yes | One-sentence description embedded in the import report for human reference. Not written to `results.jsonl`; the importer never modifies result records. |

**Derived identifiers:**

```
flag_id  = f"{result_id}-{era_descriptor}"     # e.g. "de-1933"
asset_id = f"{flag_id}-wikimedia-svg"           # e.g. "de-1933-wikimedia-svg"
```

**Example rows:**

```csv
result_id,era_descriptor,era_start,era_end,display_name,wikimedia_filename,short_description
de,1933,1933,1935,Germany 1933–1935,Flag_of_Germany_(1933-1935).svg,Historical flag of Germany used from 1933 to 1935.
de,weimar,1919,1933,Germany (Weimar Republic),Flag_of_Germany_(1919-1933).svg,Flag of the Weimar Republic used from 1919 to 1933.
```

The file must have a header row. Blank lines and lines beginning with `#` are ignored.

### 4.2 `import_historical.py` Design

Follows `import_us_states.py` exactly in structure. Key differences noted.

**CLI:**

```
python scripts/import_historical.py [--seed PATH] [--dry-run] [--force]
```

- `--seed PATH`: path to `historical_seed.csv`; default `scripts/historical_seed.csv`
- `--dry-run`: load, validate, fetch metadata from Wikimedia API, but do not download SVGs or write manifest files; write report to stdout only
- `--force`: allow overwriting records that already have `review_status=reviewed` (default: skip reviewed records)

**Processing loop (per seed row):**

1. Compute `flag_id`, `asset_id`.
2. If a flag record exists with `review_status=reviewed` → `outcome=skipped_existing_reviewed`; continue.
3. If `result_id` is not found in `results.jsonl` → `outcome=unknown_result_id`; continue. Do not create result records.
4. Query Wikimedia Commons API for `wikimedia_filename`:
   ```
   action=query, titles=File:{wikimedia_filename}, prop=imageinfo,
   iiprop=url|extmetadata, iiextmetadatafilter=LicenseShortName|Artist|Credit
   ```
   - On API failure → `outcome=failed_fetch`; continue.
   - On missing page → `outcome=needs_source`; create flag record with `review_status=needs_source`. Do not create an asset record (no URL or file to reference). Skip steps 5–8.
5. Extract `source_url` (imageinfo url) and license from extmetadata. Map license string to v3 enum using the same `LICENSE_MAP` as Phase 2. If mapping fails → asset `review_status=needs_license`.
6. Download SVG to `data/sources/wikimedia/historical/{flag_id}.svg`. Skip if file exists and not `--force`.
7. Create or update flag record (see §4.3).
8. Create or update asset record (see §4.3).
9. `outcome=imported`.

**After loop:** write manifest files back (full rewrite of flags.jsonl and assets.jsonl; results.jsonl is not written). Write report to `reports/import/wikimedia/{timestamp}.json`.

**Exit codes:** 0 on success (including skips); non-zero if any `failed_fetch` or `failed_write` outcomes occurred.

### 4.3 Manifest Record Patterns

**`flags.jsonl` — new historical flag record:**

```json
{
  "flag_id": "de-1933",
  "result_id": "de",
  "display_name": "Germany 1933–1935",
  "variant": "standard",
  "status": "historical",
  "era_start": "1933",
  "era_end": "1935",
  "review_status": "imported",
  "trainable": false
}
```

Fields `era_start` and `era_end` are omitted (not written as null) when the seed row has empty values for them.

**`assets.jsonl` — new SVG source asset record:**

```json
{
  "asset_id": "de-1933-wikimedia-svg",
  "flag_id": "de-1933",
  "asset_type": "source_original",
  "path": "data/sources/wikimedia/historical/de-1933.svg",
  "source_name": "Wikimedia Commons",
  "source_url": "https://commons.wikimedia.org/wiki/File:Flag_of_Germany_(1933-1935).svg",
  "license": "public-domain",
  "review_status": "imported",
  "trainable": false
}
```

`review_status` on the asset is `imported` when license resolved cleanly; `needs_license` when license string was present but not in the LICENSE_MAP; `needs_source` when the Wikimedia page was missing.

**`results.jsonl` — not written.** Existing result records are authoritative and must not be modified by the importer.

### 4.4 Import Report Format

Written to `reports/import/wikimedia/{timestamp}.json`. Same structure as Phase 2 reports.

```json
{
  "version": 1,
  "generated_at": "2026-05-21T120000Z",
  "importer": "import_historical",
  "source_family": "wikimedia",
  "summary": {
    "total": 30,
    "imported": 25,
    "needs_license": 2,
    "needs_source": 1,
    "skipped_existing_reviewed": 1,
    "unknown_result_id": 0,
    "failed_fetch": 1,
    "failed_write": 0
  },
  "records": [
    {
      "flag_id": "de-1933",
      "outcome": "imported",
      "flag_review_status": "imported",
      "asset_review_status": "imported"
    }
  ],
  "failures": [
    {
      "flag_id": "xx-example",
      "outcome": "failed_fetch",
      "error": "HTTP 404 from Wikimedia API"
    }
  ]
}
```

### 4.5 `validate_manifest.py` — Check for `era_start` / `era_end`

Before implementing the importer, check whether `validate_manifest.py` currently warns or errors on unknown fields in flag records. If it does, add `era_start` and `era_end` as recognized optional string fields. If it ignores extras, no change is needed.

### 4.6 Training Export Behavior

Historical flags imported with `trainable=false` and `review_status=imported` do not appear in the training export and have no effect on model training. After a human reviewer promotes records to `review_status=reviewed` and sets `trainable=true`, subsequent `export_training.py` runs include the new classes. The C binary and eval infrastructure handle them transparently — `class_meta.tsv` will contain `status=historical` for those rows, which `--identify-json` exposes in its output.

## 5. Thread B: Bot Migration to `--identify-json`

### 5.1 Files Changed

`bot/bot.py` only.

### 5.2 Imports

Add `import json` to the existing imports block. Remove `RESULT_RE`.

### 5.3 Subprocess Call

```python
# Before:
result = subprocess.run(
    [EXE, "--labels", LABELS, "--identify", tmp_path, "--weights", WEIGHTS],
    ...
)

# After:
result = subprocess.run(
    [EXE, "--labels", LABELS, "--identify-json", tmp_path, "--weights", WEIGHTS],
    ...
)
```

### 5.4 Response Parsing — replace RESULT_RE loop in `_run_identify`

```python
try:
    data = json.loads(result.stdout)
except json.JSONDecodeError:
    return (
        "error: could not parse classifier output",
        result.stdout,
        result.stderr,
    )

if not data.get("detected"):
    return "No flag found in that image.", result.stdout, result.stderr

lines = []
for r in data.get("results", []):
    emoji = flag_emoji(r["result_id"])
    prefix = f"{emoji} " if emoji else ""
    rank = r["rank"]
    name = r["display_name"]
    conf = r["confidence"]
    if rank == 1:
        line = f"{prefix}**{name}**  —  {conf:.0%}"
        desc = r.get("short_description", "").strip()
        if desc:
            line += f"\n_{desc}_"
    else:
        line = f"{rank}. {prefix}**{name}**  —  {conf:.0%}"
    lines.append(line)

ambiguity = data.get("ambiguity")
if ambiguity:
    lines.append(f"\n⚠️ {ambiguity['message']}")

parsed = "\n".join(lines) if lines else "no results returned"
return parsed, result.stdout, result.stderr
```

`flag_emoji` already handles v3 format after the Phase 4 fix: `result_id` values from `--identify-json` are bare (`"de"`, `"us-ca"`) rather than `flag_id`-style suffixed strings, so `flag_emoji("de")` → `🇩🇪` and `flag_emoji("us-ca")` → `🇺🇸` (US flag as fallback for state results, which have no Unicode flag emoji).

The existing `returncode != 0` guard runs before this block and returns early on non-zero exit; the JSON parsing block replaces only the stdout-parsing section that follows it. All surrounding structure (returncode check, stderr logging, temp-file cleanup) is unchanged.

### 5.5 `on_ready` Log

No change needed — `LABELS` is already logged from the Phase 4 fix.

## 6. Thread C: `--identify-json-batch`

### 6.1 New CLI Flag

`--identify-json-batch <file>` reads one image path per line from `<file>`. Parsed in the same argument-handling block as `--identify-json` and other named flags in `main()`.

### 6.2 Output Format

Newline-delimited JSON to stdout. Each output line is a complete, self-contained JSON object in the same schema as `--identify-json` single-image output. Empty lines in the input file are skipped silently.

```
{"input_path": "path/a.png", "detected": true, "results": [...], "detection": {...}}
{"input_path": "path/b.png", "detected": false, "results": [], "no_flag_reason": "below_threshold"}
```

No wrapping array. Each line is independently parseable.

### 6.3 C Implementation

**Refactor `identify_flag_json` into a per-path helper.**

The existing `identify_flag_json` function currently reads its path from the parsed arg and writes JSON to stdout for a single image. Extract the core body into a new static function:

```c
static void identify_flag_json_one(
    const char         *path,
    const VxDataset    *dataset,
    VxViT              *vit,
    const VxClassMeta  *meta,
    int                 n_meta,
    const VxConfusablePair *pairs,
    int                 n_pairs
);
```

This function writes exactly one JSON object (terminated by `\n`) to stdout.

`identify_flag_json` becomes a thin wrapper that calls `identify_flag_json_one` with the existing loaded state.

**Batch handler in `main()`:**

```c
// When --identify-json-batch <file> is parsed:
VxClassMeta *meta = NULL;
int n_meta = 0;
VxConfusablePair *pairs = NULL;
int n_pairs = 0;
meta  = vx_class_meta_load(labels_path, dataset.count, &n_meta);
pairs = vx_confusable_pairs_load(labels_path, &n_pairs);

FILE *batch_f = fopen(batch_json_path, "r");
// error check ...
char line[4096];
while (fgets(line, sizeof(line), batch_f)) {
    // trim newline
    size_t len = strlen(line);
    while (len > 0 && (line[len-1] == '\n' || line[len-1] == '\r')) line[--len] = '\0';
    if (len == 0) continue;
    identify_flag_json_one(line, &dataset, &vit, meta, n_meta, pairs, n_pairs);
}
fclose(batch_f);
free(meta);
free(pairs);
```

`vx_class_meta_load` and `vx_confusable_pairs_load` are existing functions from Phase 4. Load once outside the loop.

## 8. Explicit Non-Goals

The following are explicitly out of scope for Phase 5. Do not implement or speculate on them here.

- **Flags of defunct states** — USSR, East Germany, Czechoslovakia, Yugoslavia, Ottoman Empire, Austro-Hungarian Empire, etc.; deferred to Phase 6 which will require new result records
- **No-flag class, flagness head, hard-negative mining** — separate spec required
- **`exp-balanced-sampling`** — deferred; low expected value until Phase 6+ multi-source expansion creates meaningful per-class asset imbalance
- **Expansion to fictional, pride, cultural, maritime, military flags** — deferred
- **`--identify` text format changes** — unchanged
- **`--identify-batch` TSV changes** — unchanged
- **Committing historical SVG source assets** — local only by default; only small well-licensed assets should be committed intentionally
- **Direct JSONL parsing in the C binary** — C consumes generated TSV and CSV; JSONL stays in Python tooling
- **SQLite manifest** — JSONL remains canonical
- **Category-aware augmentation for historical flags** — deferred; follow evaluation evidence
