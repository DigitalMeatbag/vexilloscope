# vexilloscope v3 Phase 4 Specification: Model Experiments and Structured Output

> **Purpose:** Implementation specification for vexilloscope v3 Phase 4. Derived from `FOUNDATION_V3.md` and building on `SPEC_V3_PHASE3_EVAL.md` and its predecessors. This document covers: the `--identify-json` structured output mode, the supporting data pipeline (`class_meta.tsv`, `confusable_pairs.tsv`), the threshold constant update, and two model experiments (`exp-balanced-sampling`, `exp-256-p16`). Do not implement anything in a later phase from this document.

---

## 1. Purpose and Scope

Phase 4 has two separable threads that build on the Phase 3 evaluation baseline.

**Thread A — Structured Output Infrastructure:**
- `scripts/export_training.py` updated to generate `class_meta.tsv` and `confusable_pairs.tsv` alongside the existing labels.csv and class_map.json
- New C structs `VxClassMeta` and `VxConfusablePair` with load functions in `src/main.c`
- `--identify-json <path>` flag added to the C binary: runs the existing identify_flag pipeline, reads class_meta.tsv and confusable_pairs.tsv, and writes a JSON result object to stdout
- `VX_DETECT_THRESHOLD_X10` constant raised from 20 to 35 (see §2 for limitation note)
- New enum constant `VX_AMBIGUITY_MARGIN` for the confusable-aware ambiguity gate

**Thread B — Model Experiments:**
- `exp-balanced-sampling`: class-balanced training sampling strategy; assesses whether the current round-robin cycling disadvantages any class
- `exp-256-p16`: 256×256 input resolution with 16×16 patches; assesses whether higher-resolution input improves accuracy on seal-heavy or detail-heavy confusable pairs

Both threads require the Phase 3 baseline (`reports/eval/v3-baseline/`) as a committed starting point. Thread A is a committed deliverable. Thread B produces evidence for Phase 5 planning.

**Phase 4 delivers:**

- Updated `scripts/export_training.py`: generates `class_meta.tsv` and `confusable_pairs.tsv`
- `data/generated/train/class_meta.tsv` — per-class inference metadata (gitignored, regenerable)
- `data/generated/train/confusable_pairs.tsv` — confusable pair list for ambiguity detection (gitignored, regenerable)
- Updated `src/main.c`: new enum constants, `VxClassMeta`/`VxConfusablePair` structs, load functions, softmax helper, JSON string escaper, `--identify-json` mode
- `reports/eval/exp-balanced-sampling/` and `reports/eval/exp-256-p16/` — local eval reports (not committed unless designated as a new milestone)

**Phase 4 does not touch:**

- `--identify` text output format (unchanged)
- `--identify-batch` TSV output (unchanged)
- Discord bot (`bot/bot.py`)
- Manifest JSONL files or `scripts/validate_manifest.py`
- Training loop other than the sampling strategy addition for `exp-balanced-sampling`
- `reports/eval/v3-baseline/` (immutable)
- The `no_flag` training class (deferred entirely)
- Historical, fictional, or any new flag category import (deferred to Phase 5)

## 2. Foundation Decisions Summary

All decisions below are closed in `FOUNDATION_V3.md` and are not re-opened in this spec.

| Decision | Value |
|---|---|
| Structured output flag | `--identify-json <path>`; preserves existing `--identify` text contract |
| JSON output format | Ranked result objects with matched flag details, detection metadata, confidence/margin, optional ambiguity |
| Confidence definition | `softmax(avg_tta_logits)[class_id]` for the predicted class |
| Margin definition | `confidence[rank_n] − confidence[rank_n+1]`; `null` for rank-3 (no rank-4 in output) |
| Ambiguity trigger | top-1 and top-2 result_ids in the same reviewed confusable group AND `margin < VX_AMBIGUITY_MARGIN / 100.0` |
| Metadata source in C | TSV files generated by the export pipeline; no JSONL parsing in the C binary |
| class_meta.tsv | Per-class TSV indexed by class_id; fields include `short_description` sourced from `results.jsonl` |
| confusable_pairs.tsv | Flat list of all reviewed confusable pairs; one row per (A, B) combination within each group |
| `VX_DETECT_THRESHOLD_X10` | 20 → 35; chosen to begin reducing gross FP count at the margin without severely impacting true-positive recall. **Limitation:** the v3-baseline negative eval shows 100% FP rate at x10=5–30; 99.3% at x10=35; 98.8% at x10=40. 19.67% high-confidence FP persists at x10=35 and x10=40 alike — the 19 high-confidence false positives are not affected by threshold changes in the swept range. This change marginally reduces gross FP count but does not solve the FP problem. Threshold calibration alone is insufficient; the FP problem is deferred. |
| Experiment run strategy | Two independent training runs with separate run-ids; compare each against v3-baseline independently |
| `exp-balanced-sampling` | Change training sampling from round-robin to uniform random class selection; isolate class distribution effect |
| `exp-256-p16` | `VX_IMAGE_H/W = 256`, `VX_PATCH_H/W = 16`; preserves 256-token count; tests higher-resolution input |
| Image regeneration for 256 | Not required; training exports already at 512×512 PNG; `img_load` bilinear-resizes at load time |
| Phase 4 complete definition | `--identify-json` operational AND at least one experiment eval report compared against v3-baseline |

## 4. Data Pipeline: class_meta.tsv and confusable_pairs.tsv

`scripts/export_training.py` generates two new files in the output directory alongside the existing labels.csv and class_map.json.

### 4.1 class_meta.tsv

**Path:** `data/generated/train/class_meta.tsv`

**Purpose:** Per-class inference metadata for the C binary's `--identify-json` mode. Provides all fields needed to construct a JSON result object without JSONL parsing in C.

**Format:**
- UTF-8 encoding, LF line endings.
- First line is a tab-separated header:
  ```
  class_id	result_id	flag_id	display_name	category	fictionality	status	variant	short_description
  ```
- One data row per class, sorted by class_id ascending (same order as labels.csv and class_map.json).
- Row count excluding header equals n_classes (306 at Phase 4 baseline).
- Tabs and newlines within field values are replaced with a single space before writing.
- No quoting; after substitution, no field value contains a raw tab or newline.

**Field definitions:**

| Column | Source | Notes |
|---|---|---|
| `class_id` | computed | 0-based index; matches class_map.json `class_id` |
| `result_id` | `flags.jsonl` → `result_id` | stable result identifier |
| `flag_id` | `flags.jsonl` → `flag_id` | exact visual identity class |
| `display_name` | `results.jsonl` → `display_name` | human-facing name |
| `category` | `results.jsonl` → `category` | e.g. `national`, `subnational` |
| `fictionality` | `results.jsonl` → `fictionality` | `nonfiction` or `fictional` |
| `status` | `flags.jsonl` → `status` | `current`, `historical`, etc. |
| `variant` | `flags.jsonl` → `variant` | `standard`, `construction-sheet`, etc. |
| `short_description` | `results.jsonl` → `short_description` | may be empty string if absent from manifest |

The class ordering in class_meta.tsv must exactly match the ordering in labels.csv and class_map.json: sorted by flag_id, the same sort used by the existing `eligible_flags` loop. Row N (1-based, excluding header) has `class_id = N − 1`.

**Example rows:**
```
class_id	result_id	flag_id	display_name	category	fictionality	status	variant	short_description
0	ad	ad-current	Andorra	national	nonfiction	current	standard	Current national flag of Andorra.
1	ae	ae-current	United Arab Emirates	national	nonfiction	current	standard	Current national flag of the United Arab Emirates.
```

### 4.2 confusable_pairs.tsv

**Path:** `data/generated/train/confusable_pairs.tsv`

**Purpose:** Flat list of reviewed confusable pairs for ambiguity detection in the C binary. Each row represents one (A, B) pair within a confusable group. The C binary does a linear scan over these rows.

**Format:**
- UTF-8 encoding, LF line endings.
- First line is a tab-separated header:
  ```
  confusable_id	level	member_a	member_b
  ```
- One row per ordered combination of two members within each reviewed confusable group.
- For a group with N members, there are N×(N−1)/2 rows.
- Only `review_status=reviewed` entries from `data/manifest/confusables.jsonl` participate.
- Tabs within field values are replaced with a space.

**Field definitions:**

| Column | Description |
|---|---|
| `confusable_id` | From `confusables.jsonl`; identifies the group |
| `level` | `result` or `flag`; determines which ID type to compare at runtime |
| `member_a` | First member ID (`result_id` if `level=result`; `flag_id` if `level=flag`) |
| `member_b` | Second member ID (same type as `member_a`) |

Each pair appears exactly once; the C matching code checks both orientations (A matches result_id_1 AND B matches result_id_2, or vice versa).

**Example rows:**
```
confusable_id	level	member_a	member_b
ro-td	result	ro	td
```

### 4.3 export_training.py Changes

The following additions are made to `scripts/export_training.py`. All existing behavior is preserved.

**1. Extract `short_description` from loaded results:**

`results.jsonl` is already loaded via `vm.validate()` and accessible as `results = loaded["results"]`. Access `short_description` per result_id:

```python
# When building class_entries and writing class_meta.tsv:
short_desc = results.get(result_id, {}).get("short_description", "")
```

**2. Generate `class_meta.tsv` after writing `class_map.json`:**

```python
def _clean(s):
    return str(s).replace("\t", " ").replace("\n", " ")

class_meta_path = output_dir / "class_meta.tsv"
with open(class_meta_path, "w", encoding="utf-8", newline="\n") as f:
    f.write("class_id\tresult_id\tflag_id\tdisplay_name\tcategory\tfictionality\tstatus\tvariant\tshort_description\n")
    for class_id, (fid, flag, result, *_) in enumerate(eligible_flags):
        short_desc = _clean(result.get("short_description", ""))
        row = "\t".join([
            str(class_id),
            _clean(result.get("result_id", "")),
            _clean(fid),
            _clean(result.get("display_name", "")),
            _clean(result.get("category", "")),
            _clean(result.get("fictionality", "")),
            _clean(flag.get("status", "")),
            _clean(flag.get("variant", "")),
            short_desc,
        ])
        f.write(row + "\n")
```

**3. Generate `confusable_pairs.tsv` after writing `class_meta.tsv`:**

Add `import itertools` to the file-level imports at the top of `export_training.py` (with the other standard library imports). Then add the following block inside `main()`:

```python
confusables_path = REPO_ROOT / "data" / "manifest" / "confusables.jsonl"
confusable_pairs_path = output_dir / "confusable_pairs.tsv"
pairs = []
if confusables_path.exists():
    with open(confusables_path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            rec = json.loads(line)
            if rec.get("review_status") != "reviewed":
                continue
            cid = rec["confusable_id"]
            level = rec["level"]
            members = rec["members"]
            for a, b in itertools.combinations(members, 2):
                pairs.append((cid, level, a, b))
with open(confusable_pairs_path, "w", encoding="utf-8", newline="\n") as f:
    f.write("confusable_id\tlevel\tmember_a\tmember_b\n")
    for cid, level, a, b in pairs:
        f.write(f"{cid}\t{level}\t{a}\t{b}\n")
```

`itertools` is standard library; no new `requirements.txt` entries needed.

**4. Update report output:**

Add after the `class_map.json` print line:
```python
print(f"  class_meta.tsv:       {class_meta_path}")
print(f"  confusable_pairs.tsv: {confusable_pairs_path}")
```

The C trainer invocation line is unchanged; `class_meta.tsv` and `confusable_pairs.tsv` are used at inference, not training.

### 5.1 New Enum Constants

Add the following to the `enum` at the top of `src/main.c`:

```c
VX_AMBIGUITY_MARGIN  = 10,  /* ambiguity gate: emit when margin < this / 100.0 */
VX_BALANCED_SAMPLING =  0,  /* 0 = round-robin (baseline default), 1 = class-balanced random */
```

Change `VX_DETECT_THRESHOLD_X10` from 20 to 35:

```c
VX_DETECT_THRESHOLD_X10 = 35,  /* raised from 20; see SPEC_V3_PHASE4_MODEL_OUTPUT.md §2 */
```

For `exp-balanced-sampling`: set `VX_BALANCED_SAMPLING = 1`, recompile, train, revert to 0 after.
For `exp-256-p16`: set `VX_IMAGE_H = VX_IMAGE_W = 256`, `VX_PATCH_H = VX_PATCH_W = 16`, recompile, train, restore or adopt after.

`VX_PATCH_SIZE` and `VX_N_PATCHES` are computed expressions in the enum (`VX_PATCH_H * VX_PATCH_W * VX_IMAGE_C` and `(VX_IMAGE_H / VX_PATCH_H) * (VX_IMAGE_W / VX_PATCH_W)`) and update automatically with the resolution change. No other architectural changes are needed for the 256 experiment.

**`VX_DETECT_THRESHOLD_X10 = 35` and `VX_AMBIGUITY_MARGIN = 10` are permanent production changes.** They are committed to the main codebase immediately and are not conditional on experiment outcome.

### 5.2 VxClassMeta Struct

typedef struct {
    int   class_id;

### 5.4 Load Functions

Add the following static functions to `src/main.c`.

**`vx_class_meta_load`**

```c
static VxClassMeta *vx_class_meta_load(const char *labels_path, int *out_n);
```

- Derives the `class_meta.tsv` path: replaces the filename portion of `labels_path` with `class_meta.tsv` (same directory).
- Opens the file. If missing, prints an error to stderr and exits non-zero.
- Reads and discards the header line.
- Parses each subsequent line as a tab-separated row. First field is `class_id` (integer); remaining fields are strings copied into the struct.
- Validates that `class_id` values are exactly 0, 1, 2, … N−1 in sequence. Exits non-zero if the sequence breaks.
- Allocates and returns a `VxClassMeta` array of length N. Sets `*out_n = N`.
- Exits non-zero if any string field exceeds its buffer size.

**`vx_confusable_pairs_load`**

```c
static VxConfusablePair *vx_confusable_pairs_load(const char *labels_path, int *out_n);
```

- Derives the `confusable_pairs.tsv` path: same directory as `labels_path`, filename `confusable_pairs.tsv`.
- If the file does not exist or cannot be opened: sets `*out_n = 0` and returns `NULL`. Absence is non-fatal; ambiguity detection is disabled when `n_pairs = 0`.
- Reads and discards the header line.
- Parses each row: `confusable_id`, `level` string, `member_a`, `member_b`.
- Sets `level`: 0 for `"result"`, 1 for `"flag"`. Exits non-zero on unrecognized `level` value.
- Returns array of length N; sets `*out_n = N`.

### 5.5 Softmax Helper

Add to `src/main.c`:

```c
static void vx_softmax(const float *logits, float *probs, int n) {
    float max_l = logits[0];
    for (int i = 1; i < n; i++) if (logits[i] > max_l) max_l = logits[i];
    float sum = 0.0f;
    for (int i = 0; i < n; i++) { probs[i] = expf(logits[i] - max_l); sum += probs[i]; }
    for (int i = 0; i < n; i++) probs[i] /= sum;
}
```

### 5.6 JSON String Escape Helper

Add to `src/main.c`:

```c
static void vx_json_write_string(FILE *f, const char *s) {
    fputc('"', f);
    for (; *s; s++) {
        unsigned char c = (unsigned char)*s;
        if      (c == '"')  fputs("\\\"", f);
        else if (c == '\\') fputs("\\\\", f);
        else if (c < 0x20)  fprintf(f, "\\u%04x", c);
        else                fputc(c, f);
    }
    fputc('"', f);
}
```

Used for all string values in JSON output. Float and integer fields use `fprintf` directly.

## 6. C Binary: --identify-json Mode

### 6.1 Flag Syntax

```
--identify-json <path>
```

- `<path>`: path to the input image. Same supported formats as `--identify` (PNG, JPEG via stb_image).
- Requires `--labels` to be set (the labels_path is used to locate `class_meta.tsv` and `confusable_pairs.tsv`).
- `--identify` and `--identify-json` are mutually exclusive. If both are present, the binary exits non-zero with a usage error.
- May be combined with `--detect-threshold-x10` (same semantics as with `--identify`).
- May be combined with `--weights`.
- Not compatible with `--eval-dump` or training mode (positional image directories). If both `--identify-json` and positional training args are present, treat as training mode with a usage error about `--identify-json`.

### 6.2 Execution Path

When `--identify-json <path>` is present:

1. Load labels.csv → `VxDataset` (unchanged).
2. Load weights → `VxViT` (unchanged).
3. Load `class_meta.tsv` → `VxClassMeta[]` via `vx_class_meta_load`. Exit non-zero if load fails.
4. Load `confusable_pairs.tsv` → `VxConfusablePair[]` via `vx_confusable_pairs_load`. On failure (file missing), set `n_pairs = 0` and continue (ambiguity detection disabled).
5. Validate `n_meta == vit.n_labels`. If they differ, print both values to stderr and exit non-zero.
6. Run the identification pipeline:
   - `img_load_native(path, VX_DETECT_MAX_DIM, VX_IMAGE_C, &H, &W)` — loads image, caps longer edge to 1024.
   - Sliding window scan (identical to `identify_flag`): score full image as scale-1; if `scale1_logit < VX_DETECT_SKIP_SUBWINDOWS_X10 / 10.0f`, also score 75% and 50% sub-windows. Track `best_y0`, `best_x0`, `best_crop_h`, `best_crop_w`, `best_logit`.
   - Threshold gate: if `best_logit < detect_threshold_x10 / 10.0f`, emit no-flag JSON (§7.2) and return 0.
   - TTA: re-extract best window, run `VX_IDENTIFY_TTA` augmented passes, accumulate `avg_logits` (identical to `identify_flag`).
   - Compute top-3 indices via `topk_indices(avg_logits, n, k, top_indices)` (same as `identify_flag`).
7. Compute softmax: `vx_softmax(avg_logits, probs, n)`.
8. Compute per-rank confidence and margin:
   - `confidence[r] = probs[top_indices[r]]` for r = 0, 1, 2.
   - `margin[0] = confidence[0] - confidence[1]`
   - `margin[1] = confidence[1] - confidence[2]`
   - `margin[2]` is null (no rank-4 in output). For rank-3, emit the 4-character literal `null` in the JSON — do not call `fprintf` with `"%.4f"` on any sentinel float; special-case `r == 2` in the result serialization loop.
9. Check ambiguity (only when `n_pairs > 0`):
   - `rid1 = class_meta[top_indices[0]].result_id`; `rid2 = class_meta[top_indices[1]].result_id`
   - `fid1 = class_meta[top_indices[0]].flag_id`; `fid2 = class_meta[top_indices[1]].flag_id`
   - Scan `confusable_pairs` array. For each pair: match when `(level=0 AND {member_a,member_b}=={rid1,rid2})` OR `(level=1 AND {member_a,member_b}=={fid1,fid2})`. Both orientations (A==id1,B==id2 and A==id2,B==id1) count as a match.
   - If a match is found AND `margin[0] < VX_AMBIGUITY_MARGIN / 100.0f`: set `has_ambiguity = 1`; record `confusable_id`, `related_result_ids = {rid1, rid2}`.
10. Serialize to JSON (§7) and print to stdout.
11. Free `probs`, `avg_logits`, `class_meta`, `confusable_pairs`, VxDataset, VxViT.

### 6.3 No Side Effects on Other Modes

`--identify-json` does not write any files other than stdout. It does not change training behavior, `--identify` text output, or `--identify-batch` TSV output. The binary's existing modes are unchanged when `--identify-json` is absent.

```json
"ambiguity": {
  "type": "known_confusable",
  "message": "Top results are visually similar and confidence margin is small.",
  "related_result_ids": ["ro", "td"]
}
```

#### Result object fields

| Field | Type | Description |
|---|---|---|
| `rank` | integer | 1-based rank in descending logit order. Always 1, 2, or 3. |
| `result_id` | string | Stable result identifier from `class_meta.tsv`. |
| `display_name` | string | Human-facing name. |
| `category` | string | `national`, `subnational`, etc. |
| `fictionality` | string | `nonfiction` or `fictional`. |
| `status` | string | `current`, `historical`, etc. |
| `short_description` | string | Context sentence; empty string `""` if absent from manifest. |
| `matched_flag_id` | string | The `flag_id` of the predicted class (from `class_meta.tsv`). |
| `matched_variant` | string | Variant of the predicted class. |
| `confidence` | float | `softmax(avg_tta_logits)[class_id]`. Serialized with `"%.4f"`. |
| `margin` | float or null | `confidence[rank_n] − confidence[rank_n+1]`. `null` for rank-3. Serialized with `"%.4f"` or `null`. |

#### Detection object fields

| Field | Type | Description |
|---|---|---|
| `crop.x` | integer | Left edge of the best window in the scaled image, pixels. |
| `crop.y` | integer | Top edge of the best window in the scaled image, pixels. |
| `crop.width` | integer | Width of the best window in the scaled image, pixels. |
| `crop.height` | integer | Height of the best window in the scaled image, pixels. |
| `score` | float | Pre-TTA logit of the best window (`best_logit`). Serialized with `"%.4f"`. |
| `scaled_image_size.width` | integer | Width W of the image as loaded by `img_load_native` (after `VX_DETECT_MAX_DIM = 1024` cap). |
| `scaled_image_size.height` | integer | Height H of the same loaded image. |

`crop` and `scaled_image_size` share the same coordinate space: the image after `img_load_native`. For a full-image detection (scale-1 winner), `crop = {x:0, y:0, width:W, height:H}` and `scaled_image_size = {width:W, height:H}`.

#### Ambiguity object fields

| Field | Type | Description |
|---|---|---|
| `type` | string | `"known_confusable"` — only value emitted in Phase 4. |
| `message` | string | Fixed string: `"Top results are visually similar and confidence margin is small."` |
| `related_result_ids` | array of strings | `[result_id of top-1, result_id of top-2]`. |

`"ambiguity": null` when `has_ambiguity = 0` or ambiguity detection is disabled (`n_pairs = 0`).

### 7.2 No-Flag Detection

When `best_logit < detect_threshold_x10 / 10.0f`, write to stdout:

```json
{
  "input_path": "path/to/image.png",
  "detected": false,
  "results": [],
  "no_flag_reason": "below_threshold"
}
```

`no_flag_reason` values in Phase 4:

| Value | Condition |
|---|---|
| `"below_threshold"` | `best_logit < detect_threshold_x10 / 10.0f` — the standard no-flag case |
| `"no_detection"` | No valid scan windows were produced (all sub-window sizes fell below `VX_DETECT_MIN_CROP`; extremely rare, requires very small input) |

`"low_confidence"` is a Foundation-reserved value; it is not emitted in Phase 4.

### 7.3 Formatting Rules

- All floats use `"%.4f"` format.
- All integers use `"%d"` format.
- All JSON string values pass through `vx_json_write_string` (§5.6).
- `null` is the 4-character literal `null`, not a quoted string.
- The JSON object is terminated with a trailing newline (`\n`).
- Compact or indented formatting are both acceptable; the examples in §7.1 and §7.2 show indented format for readability only.
- The output must be valid JSON as parsed by Python's `json.load`.

## 8. Model Experiments

### 8.1 Overview

No image regeneration is needed. Training exports are already 512×512 PNG; `img_load(path, H, W, C)` bilinear-resizes at load time regardless of the H/W enum values.

### 8.2 exp-balanced-sampling

**Rationale:** The current training loop cycles over all image sources in round-robin order (primary, wiki, emoji). If a class lacks a wiki or emoji asset, its NULL entry falls back to primary, creating uneven effective sampling when source coverage is non-uniform. Class-balanced sampling ensures each class receives equal expected training attention regardless of how many source images it has.

**Expected value:** Low at Phase 4 with the current single-source-dominated dataset. Primary value is infrastructure: de-risks Phase 5 multi-source expansion where sampling imbalance matters more.

**Code change in `src/main.c`:**

Set `VX_BALANCED_SAMPLING = 1` in the enum.

In the training loop, replace the index computation. The current code (paraphrased):
```c
int idx = (step - 1) % n_images;
int class_idx = idx % n_flags;
Tensor *sample = images[idx];
if (!sample) sample = images[class_idx];
```

With:
```c
int class_idx, img_idx;
if (VX_BALANCED_SAMPLING) {
    class_idx = rand() % n_flags;
    int n_dirs = n_images / n_flags;   /* 1, 2, or 3 */
    int src    = rand() % n_dirs;
    img_idx    = src * n_flags + class_idx;
    if (!images[img_idx]) img_idx = class_idx;  /* fall back to primary */
} else {
    int idx = (step - 1) % n_images;
    class_idx = idx % n_flags;
    img_idx   = idx;
}
Tensor *sample = images[img_idx];
if (!sample) sample = images[class_idx];
```

`n_dirs = n_images / n_flags` is computable from the existing `n_images` and `n_flags` variables already in scope at that point in the training loop.

```

(If wiki or emoji dirs are not present, omit them; use however many dirs are available — same as v3-baseline invocation.)

After training, rename weights to avoid overwriting the production file:

```

### 8.3 exp-256-p16

**Rationale:** The v3-baseline uses 128×128 input with 8×8 patches (256 tokens). Confusable group confusion matrices from the baseline may show seal-heavy or fine-detail flags (e.g., coats-of-arms or emblems) account for a disproportionate share of errors. Higher-resolution input (256×256) with proportionally larger patches (16×16) preserves the 256-token count while giving the patch linear projection access to more visual detail per token.

**Code change in `src/main.c`:**

Revert `VX_BALANCED_SAMPLING = 0`. Change resolution/patch constants:

```c
VX_IMAGE_H  = 256,
VX_IMAGE_W  = 256,
VX_PATCH_H  = 16,
VX_PATCH_W  = 16,
```

`VX_PATCH_SIZE` becomes `16×16×3 = 768` (was 192). `VX_N_PATCHES` remains `(256/16)×(256/16) = 256`. All downstream tensor shapes update automatically from these expressions.

**Impact on model size:**
- `PatchEmb`: `[768 × 128]` = 98,304 parameters (vs. 24,576 at baseline; 4× larger)
- `PosEmb`: `[256 × 128]` = 32,768 parameters (unchanged)
- Encoder, `Wout`: unchanged

**Training invocation:** Same as exp-balanced-sampling above.

After training:
```powershell
Rename-Item vit_weights.bin vit_weights_256p16.bin
```

**Eval invocation:**

```powershell
python scripts/eval_report.py --eval-dump data/generated/train/eval_dump.csv --class-map data/generated/train/class_map.json --run-id exp-256-p16 --output reports/eval/exp-256-p16

python scripts/eval_negatives.py --binary .\build\Release\vexilloscope.exe --labels data/generated/train/labels.csv --threshold-x10-base 35 --fn-image-dir data/generated/train/images --eval-report reports/eval/exp-256-p16/eval.json --run-id exp-256-p16 --output reports/eval/exp-256-p16
```

**Comparison:** Primary metric: aggregate `result_top1`. Focus metric: confusable group margins (do detail-sensitive confusable pairs improve?). Record in §9.3 comparison table.

### 8.4 Enum State After Experiments

After both experiments are complete and findings are recorded:

- **`VX_DETECT_THRESHOLD_X10 = 35` and `VX_AMBIGUITY_MARGIN = 10`** are permanent. Do not revert.
- **`VX_BALANCED_SAMPLING = 0`** is the production default unless exp-balanced-sampling shows clear improvement. If it does, set to 1 as the new production default and retrain from scratch.
- **`VX_IMAGE_H/W = 128`, `VX_PATCH_H/W = 8`** are the production defaults unless exp-256-p16 shows meaningful improvement. If it does, adopt the 256 constants, retrain from scratch, and run a new full eval to establish the new baseline.

Threshold and ambiguity constant commits do not require a new training run. Resolution and sampling changes require a full retrain and new baseline eval.

## 13. Explicit Non-Goals

The following are explicitly out of scope for Phase 4. Do not implement or speculate on them here.

- **`no_flag` training class** — deferred entirely; the v3-baseline negative eval shows 100% FP rate at x10=5–30, 99.3% at x10=35, and 98.8% at x10=40, with 19.67% high-confidence FP persisting unchanged across all three levels; threshold calibration alone cannot solve this; a solution (flagness head, separate detector, hard-negative mining) requires its own spec
- **Historical flag import** — deferred to Phase 5 (`SPEC_V3_PHASE5_HISTORICAL.md`)
- **`--identify-json-batch`** — deferred; Phase 4 adds single-image JSON mode only
- **Discord bot migration to `--identify-json`** — deferred; bot continues using `--identify` text output until Phase 5+
- **`256×256` with `8×8` patches (1024 tokens)** — not in Phase 4 experiments; token cost is too high for an exploratory run; evaluate after `exp-256-p16` results are known
- **CLS token, convolutional stem, mixup/cutmix, increased capacity** — evidence-gated per Foundation §Model Direction; defer until baseline analysis motivates them
- **Category-aware augmentation** — deferred
- **Hard-negative mining** — deferred; no-flag problem is not addressed in Phase 4
- **Augmented or real-photograph negative eval set** — deferred; Phase 3 synthetic negatives remain the negative eval dataset
- **Committing experiment eval reports** — local only; only a new declared baseline would be committed
- **`short_description` added to `class_map.json`** — `class_map.json` format is unchanged; inference metadata lives in `class_meta.tsv`
- **`--force` re-run or modification of `reports/eval/v3-baseline/`** — the v3-baseline is immutable once committed
- **Fictional, pride, cultural, maritime, or military flag expansion** — deferred
- **SQLite manifest** — JSONL remains canonical
- **Direct JSONL parsing in the C binary** — C consumes generated TSV and CSV; JSONL stays in Python tooling
